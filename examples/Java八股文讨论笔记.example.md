# Java 八股文讨论笔记

---

## 批次 1（2026-11-05）

### Q1: 为什么说 Java 是跨平台的语言？

**A:** **编译一次，得到一份"通用稿子"（字节码），每个平台装个"翻译"（JVM）来跑。**

- 源码 `.java` → `javac` → `.class` 字节码（不绑定任何 CPU/OS）
- Windows/Linux/Mac 各有对应 JVM 实现，同一份字节码在满足版本和依赖要求时可跨平台运行

**关键追问**：JVM 本身跨平台吗？—— **规范是平台无关的，具体 JVM 程序要适配操作系统和 CPU。**

**什么时候破功**：调 JNI 本地方法、路径分隔符写死、依赖平台特定库。

---

### Q2: JDK、JRE、JVM 三者什么关系？（累计提问 3 次）

**A:** **套娃：JVM 是发动机 → JRE 是能跑的车 → JDK 是带全套修车工具的车。**

| | 包含 | 给谁用 |
|---|---|---|
| JVM | 执行字节码的虚拟机（HotSpot 含解释器、JIT、内存管理） | 不直接面向人 |
| JRE | JVM + 基础类库 | 只**运行** Java 程序 |
| JDK | JRE + javac/javadoc/jdb 等开发工具 | 要**写** Java 代码 |

**易错点**：上面的套娃图是传统组成关系。JDK 9 起采用模块化布局，JDK 内不再嵌套旧式 `jre/` 目录；Oracle 从 JDK 11 起不再提供该版本的独立 JRE 下载。需要精简运行时可 `jlink` 生成专用运行时。

## 批次 2（2026-11-06）

### Q3: 啥是编译，啥是解释？区别在哪？

**A:** **编译是把一种代码转换成另一种代码；解释是解释器执行源码或中间表示所描述的操作。** 两者可组合。

| | 编译 | 解释 |
|---|---|---|
| 做什么 | 生成另一种代码（机器码/字节码），可在运行前或运行中 | 执行源码或字节码，不要求先生成本地机器码文件 |
| 速度 | 编译成本地机器码后执行快，但编译本身有成本 | 有解释调度开销，也可结合优化，实际看实现 |
| 跨平台 | 看产物：本地机器码绑定目标平台 | 看解释器与依赖，不是天然到处能跑 |

**别被类比骗了**："一句一句翻"只是入门说法，解释器实际执行的是字节码这类中间表示，不是按源码行执行。

**Java 常见路线**：源码编译成字节码，运行时解释 + JIT；**CPython** 也是先编译成字节码再解释。

---

### Q4: C、Java、Python 在"编译 vs 解释"光谱上怎么排？

**A:** **按常见实现比较：C 通常提前编译成本地机器码；Java（HotSpot）编译成字节码 + 运行时解释/JIT；Python（CPython）也先编译成字节码再解释。**

**一句话记忆**：C 是"提前编译成本地程序"，Java 和 CPython 都有"先编译成字节码"这一步，之后的执行与优化策略不同。

**别踩的坑**：不能只凭"多了一层 JVM"就断定 Java 一定比 C 慢，预热、JIT 优化、任务类型都会影响结果。
